FACULTY INSTRUCTIONAL LOAD BALANCE ANALYZER - PROJECT DETAIL EXPLANATION
================================================================================

1. EXECUTIVE SUMMARY
-------------------
The Faculty Instructional Load Balance Analyzer is a full-stack web application 
designed for ABC Engineering College. Its primary purpose is to manage and 
balance the teaching workload of faculty members. The system automates 
timetable management, work assignments, leave requests, and performance 
tracking, ensuring a fair distribution of instructional hours across departments.

2. TECH STACK OVERVIEW
---------------------
- Backend:
  * Java 17
  * Spring Boot 3.2.3
  * Spring Security (JWT-based Authentication)
  * Spring Data JPA
  * MapStruct (Entity-DTO Mapping)
  * Lombok (Boilerplate reduction)
  * Apache POI (Excel Export)
  * PostgreSQL (Database)

- Frontend:
  * React 19
  * Material UI (MUI 7)
  * Axios (API Interaction)
  * Chart.js (Data Visualization)
  * React Router (Navigation)

3. ARCHITECTURE & PATTERNS
-------------------------
The project follows a modern decoupled architecture:

- BACKEND PATTERNS (Layered Architecture):
  1. Controller Layer: Handles REST API requests and responses. Uses 
     ResponseEntity for standard HTTP communication.
  2. Service Layer: Contains core business logic, algorithm for work 
     generation, and transactional management (@Transactional).
  3. Repository Layer: Interfaces with PostgreSQL using Spring Data JPA 
     for efficient data persistence.
  4. Security Layer: Custom JWT filter and TokenProvider for stateless, 
     secure communication between frontend and backend.
  5. Utility Layer: Helper classes for file processing and common logic.

- FRONTEND PATTERNS (Component-Based UI):
  1. Pages: High-level containers for specific features (e.g., Dashboard, 
     Work Generation).
  2. Components: Reusable UI elements (Navbar, ProtectedRoute, Modals).
  3. Services: Centralized API module (services/api.js) using Axios 
     interceptors to automatically attach JWT tokens to every request.
  4. Contexts: React AuthContext manages global user state and 
     Role-Based Access Control (RBAC).

4. DATABASE SCHEMA (PostgreSQL)
------------------------------
The system utilizes 16 integrated tables:
- core: roles, users, departments, admins, faculties.
- academic: courses, venues, sections.
- logic: timetables, timetable_slots, course_faculty_mappings.
- operational: leave_requests, work_assignments, faculty_monthly_load.
- system: notifications, password_reset_tokens.

Key Relationships:
- Users are linked to Roles for permission management.
- Faculties belong to Departments and are assigned to Courses and Slots.
- Timetables consist of multiple Slots (Theory/Lab) with assigned Venues.

5. END-TO-END DATA FLOW (Example: Work Generation)
--------------------------------------------------
1. User (HOD) triggers "Generate Work" via the frontend WorkGenerationPage.
2. The Frontend sends a POST request to /api/hod/work/generate with JWT.
3. Spring Security validates the token and the user's HOD role.
4. The Backend (WorkService) fetches the active Timetable and Leave Requests.
5. An algorithm balances the load based on faculty availability and 
   prior work assignments.
6. The Database stores the generated WorkAssignments for the week.
7. The Backend returns a success response.
8. The Frontend updates the UI and generates Notifications for faculties.

6. KEY FEATURES FOR DEVELOPMENT "PATTERN"
----------------------------------------
- Stateless Auth: JWT tokens stored in localStorage, handled by interceptors.
- Responsive Design: Material UI ensures a premium look on all devices.
- Excel Integration: Reports can be exported via Apache POI.
- Real-time Notifications: System alerts users of assignments and approvals.
- Error Handling: Global exception handling in the backend ensures 
  consistent error messages to the frontend.
